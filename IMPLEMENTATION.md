## 3D formulation

- Units: N, mm, MPa. Static, isotropic, small-strain linear elasticity.
- The meshing spike selected **conforming tetrahedra** instead of an immersed SDF with a stiffness floor. No void carries mechanical load and opposing osteotomy faces are not welded.
- Three bone solids remain distinct with no contact or friction. A developer-defined 2 mm cortical proxy uses 17,000 MPa; the core uses the supplied modulus. Proxy distance is measured to densely sampled outer-surface vertices, not clinical cortical imaging.
- Titanium uses E = 110,000 MPa, nu = 0.3. A yield assumption of 880 MPa supplies a screening margin; this is not a device-specific material certification.
- Current CAD v5 keeps plates and screws as separate closed solids. New `jaw-exact-tet-v4` jobs enforce screw-head/Tet10 plate interpolation and embedded screw/Tet4 bone interpolation through algebraic elimination. This implements an assumed perfect bond without a spring stiffness. Near-zero tie constraint error is numerical enforcement, not measured physical slip. Historical `jaw-locking-tet-v3` penalty results remain intact; the default 100 multiplier failed sensitivity checks. Overlapping material is not subtracted. Earlier CAD v3/v4 joined hardware can still be rebuilt.
- Continuous contours are triangulated with explicit holes in longitudinal/transverse coordinates, then mapped onto the registered curve. Screw CAD uses a declared 16-sided family with a blended head; maximum head chord deviation is approximately 0.032 mm. Canonical screw meshes are rigidly transformed into each registration so orientation cannot change their discretization. This is an engineering geometry approximation, not manufacturer CAD.
- Both registered support balls constrain translation in all directions. Registered bite regions distribute a normalized total load over their distal-bone nodes. Bilateral/left/right cases change actual load nodes.
- Double-precision geometry/material stiffness is assembled with Warp FEM's generic assembly. A CPU-built PyAMG hierarchy preconditions a Warp GPU V-cycle/CG solve. True residual and reactions are recomputed from the matrices, not copied from iteration targets.
- Bone uses Tet4 displacement; titanium uses Tet10 displacement. Stress and principal strain are recovered at four quadrature points per cell with the corresponding polynomial gradient and material law. Reported maxima remain unsmoothed. Display stress uses nearest cells in the same component; displacement uses nearest nodes. Display sampling is not a refined solution.
- Optional surface decimation is accepted only for closed positive volumes with bounded volume change; otherwise the checked original is retained. Tiny zero-volume numerical slivers removed during tetrahedralization are counted with their removed volume. This alone does not establish element-shape or bending accuracy.
- Analysis fingerprints include geometry, registrations, parameters, quality, model/device, source-code hashes and installed package versions. Shape hashes allow material/load studies to reuse meshes without reusing their results. Saved volume NPZ files retain connectivity, element degree, displacement, unsmoothed stress/strain, materials, loads, supports and attachment data.

## Measured local feasibility

The dedicated [calculation reliability report](docs/verification/CALCULATION_RELIABILITY.md) records the new verification work. Both original jaws passed independent reconstructed force, stress and energy checks. Six measured penalty runs failed the locked attachment-sensitivity screen. Exact constraints passed small independent multiplier/reference tests and both full-jaw preview audits. Standard meshes were generated, but repeated finer solves stopped at the available-RAM guard even after block-preserving memory changes and a lighter production preview. No mesh-convergence pass or qualified winner is claimed. New normal exact jobs automatically run an independent saved-field audit before acceptance; the app exposes audit/download controls separately from physical qualification. The earlier feasibility measurements below remain historical evidence.

Verification regression: the latest full **60-test backend run**, five frontend geometry tests, lint, TypeScript and production build passed. Both new normal app jobs completed with automatic independent audits and matching finite fields for all thirteen displayed parts: **76.5 seconds female / 170.9 seconds male** analysis time. Overall qualification remains false. See [normal-job evidence](docs/verification/production-exact-jobs.json).

The installed device is an RTX 3050 Laptop GPU with 4 GB VRAM and approximately 15.3 GB system RAM. The current `jaw-locking-tet-v3` run used **219,563 nodes / 333,618 tetrahedra / 658,689 DOFs**, **158.5 seconds GPU solve** and **221.2 seconds total**. Observed total GPU memory reached approximately **3,819 MiB**, including desktop/browser use. Preview fits narrowly; a refined whole-jaw calculation is not assumed to fit.

The current saved design's true relative residual was **7.48e-8**, relative force imbalance **2.01e-10** and relative moment imbalance **9.04e-11**. Locking-head slip was **0.00183 mm**, screw/bone slip **0.1936 mm**, peak titanium stress **19,351 MPa** and displacement **14.60 mm**. Yield, bone-attachment slip and small-strain checks fail. These values do not constitute a valid physical prediction beyond the linear model's assumptions. Results retain `qualified=false`; no verified winner is fabricated. Full fields were retained and matched all thirteen rendered part meshes.

The rectangular Hex8 length-refinement series, independent calculation and CPU/GPU comparison pass their declared checks. Independent heterogeneous Tet4 matrices agree at approximately 1.2e-16 relative error. A first-order thin-plate diagnostic showed **46.4% bending error**, so titanium was changed to quadratic displacement. The separate 1.5 mm quadratic thin-plate series gives approximately **1.19%, 0.94%, 0.89%** analytical deflection error, with **0.0545%** change between its last two levels. This verifies the method on that benchmark; it does not qualify the fitted jaw or attachments. See [measured numerical checks](docs/verification/local-3d-checks.json).

The latest full backend suite has **60 passing tests**, including exact constraints, block scaling, independent audits, memory guards, immutable preparation, ownership, field/input matching, search gating and partial exports. Five frontend geometry tests cover section perimeters, coplanar edges, empty cuts and mapping deformed picks to original coordinates. Production build, TypeScript and lint checks pass. Browser checks cover live previews, actual solving, inspection tools, revision overlays, camera bookmarks, real STL/report download, partial studies, expanded search and independent calculation checks. ## Budget and deployment

No Modal job, deployment or warm container has been created. No cloud credits were spent. Local jobs run one at a time. Single solves have a 300-second cap; studies have a 7,200-second cap and optimization has a 10,800-second cap. Isolated study/search calculations have a 360-second cap each. Cancellation terminates the owned process tree; interrupted and unrun calculations remain distinct in exported evidence.

The $30 monthly Modal balance is a ceiling, not a target. Before enabling cloud execution: configure one account, inspect remaining credit, measure a bounded solve, enforce concurrency/time/cost limits and verify result storage. The current application capability explicitly says cloud execution is unavailable even if credentials are present.

Supabase and Deepgram keys were absent during implementation. Their presence check never prints values. Configuration alone does not silently switch local storage/auth to hosted mode; follow [SERVICE_SETUP.md](SERVICE_SETUP.md).

## Removed prototype behavior

The original project synthesized a jaw from primitives, generated Gaussian stress fields, clamped stresses to story values, returned fixed GPU/residual/timing numbers, silently fell back to canned successes and described a stiffness curve as a patient cohort. Those behaviors were removed. Original specification files are retained for comparison. The current UI and reports expose uncomputed, stale, failed, cancelled, unresolved and unqualified states explicitly.
